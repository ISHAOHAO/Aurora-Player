# Aurora Player — 音视频引擎技术设计

**版本：** v1.0（基于 PRD 拆分）
**核心选型：** FFmpeg（解封装/解码）+ libass（字幕）+ libplacebo（视频处理/HDR）+ D3D11/D3D12（呈现）+ WASAPI（音频）
**铁律：** 引擎与 UI 完全解耦；解码进程崩溃不得拖垮 UI；硬件失败自动降级到软件，不直接报“无法播放”。

---

## 1. 总体架构

```text
Aurora.exe (UI Process, WebView2)
   │  IPC (JSON-RPC over named pipe, 状态推送 + 命令下发)
   ▼
Playback Controller (aurora-core.dll, C++20)
   ├── Media Engine
   │     ├── Demuxer (FFmpeg libavformat)
   │     ├── Decoder (FFmpeg libavcodec + HW accel)
   │     ├── Audio Pipeline (resample/mix → WASAPI)
   │     ├── Subtitle Pipeline (libass)
   │     ├── Video Processing (libplacebo)
   │     └── Renderer (D3D11, 可升级 D3D12)
   ├── Media Library (SQLite)
   └── Thumbnail Worker (独立进程 aurora-thumb.exe)

DLNA Service (aurora-dlna.exe, 独立进程，见 DLNA 规格文档)
```

**进程隔离原则：**
- `aurora-engine.exe`：解码+渲染宿主。崩溃后由 Controller 自动重启并恢复（文件/进度/音轨/字幕/音量），目标用户无感 ≤3 秒。
- `aurora-thumb.exe`：缩略图/海报生成，低优先级，崩溃仅重试。
- `aurora-dlna.exe`：7×24 可常驻，独立于 UI 生命周期。

## 2. 播放流水线

```text
Source (file / http / hls / dash / dlna-url)
   ↓ libavformat (demux + probe)
Stream Selection (video/audio/subtitle)
   ↓
┌─ Video Decoder ──────────────┐
│ 1. D3D11VA / DXVA2 / NVDEC   │ ← 自动协商
│ 2. HW zero-copy → D3D11 texture
│ 3. 失败 → HW copy-back
│ 4. 失败 → Software decode (dav1d 等)
└────────────┬─────────────────┘
             ▼
   Frame Queue (视频, 深度 8–16 帧)
             ▼
   libplacebo 处理链
   (去隔行 → 缩放 → 色彩/HDR → Shader → 抖动)
             ▼
   D3D11 SwapChain (全屏独占可选)
             ▼
   Display (HDR/SDR per-monitor)

┌─ Audio Decoder → 重采样/混音/EQ → Ring Buffer → WASAPI
└─ Subtitle (libass) → 渲染为 RGBA 层 → libplacebo 合成
```

**时钟：** 默认 Audio Master；Display Sync（vsync 驱动）与 Video Master 为高级选项。A/V drift 超 ±80ms 触发纠正（丢帧/重复帧），超 ±300ms 硬重新同步。

## 3. 解码与硬件加速

### 3.1 解码路径决策

```text
probe 完成 → 读取 codec/profile/level/bitdepth/resolution
   ↓
HW 能力表 (启动时枚举: D3D11VA / DXVA2 / NVDEC / QuickSync / AMF)
   ↓
匹配成功 → HW zero-copy
   ├─ init 失败 → HW copy-back
   ├─ 仍失败 → Software decode
   └─ 仍失败 → 替代解码器 → 结构化错误上报
```

### 3.2 编码支持矩阵（引擎层目标）

| 类别 | 编码 | HW 路径 | SW 兜底 |
| --- | --- | --- | --- |
| 主流 | H.264 / HEVC / AV1 / VP9 | D3D11VA/NVDEC | ✓ (dav1d for AV1) |
| 主流 | MPEG-2 / VC-1 / VP8 | D3D11VA(部分) | ✓ |
| 老旧 | DivX/Xvid/H.263/VP6/Theora/MJPEG | — | ✓ |
| 专业 | ProRes/DNxHD/DNxHR/FFV1/CineForm/HuffYUV/JPEG2000 | — | ✓ |
| 新一代 | H.266/VVC | 预留 | 实验性 |
| 中国标准 | AVS/AVS+/AVS2/AVS3 | 预留 | 预留 |

### 3.3 位深与零拷贝

- 10bit/12bit 优先 native path：`P010`/`P016` 纹理直达 libplacebo，禁止中途降 8bit。
- HW zero-copy 失败才允许 copy-back（记录性能日志）。
- HDR 元数据（mastering display、content light level、HDR10+ 动态元数据）随帧透传至渲染层。

### 3.4 容器支持

首发：MP4/M4V/MKV/AVI/MOV/WMV/ASF/TS/M2TS/MPG/MPEG/VOB/FLV/WebM/OGV/3GP/3G2/MXF/F4V/MTS/M2T/DVR-MS。
二期：ISO/BDMV/DVD Folder（无 DRM 前提；AACS 等加密内容明确提示不支持，不破解）。

## 4. 视频处理与渲染（libplacebo）

### 4.1 处理链顺序（固定）

```text
源帧 → 去隔行 → 裁剪/旋转 → Chroma 上采样 → 缩放
     → HDR Tone Mapping → Gamut Mapping → 用户 Shader
     → 蓝噪声抖动 → 输出至 SwapChain
```

### 4.2 缩放算法

| 预设档 | Upscale | Downscale |
| --- | --- | --- |
| 节能 | Bilinear | Bilinear |
| 平衡（默认） | Spline36 | Bicubic |
| 高画质 | EWA Lanczos | Spline36 |
| 极致 | EWA Jinc / FSRCNNX(实验) | EWA Lanczos |

可选全集：Bilinear / Bicubic / Lanczos / Spline16/36/64 / Catmull-Rom / Jinc / EWA 系列 / Anime4K(实验) / FSRCNNX(实验) / 自定义 Shader。

### 4.3 HDR 与色彩管理

**模式决策：**

```text
Auto 模式:
  source_hdr && display_hdr && windows_hdr_on → HDR Passthrough
  source_hdr && !display_hdr                  → HDR→SDR (tone mapping)
  !source_hdr && display_hdr                  → 原生 SDR 输出(SDR→HDR 实验功能默认关)
```

- **Tone Mapping 算法：** BT.2390 / BT.2446-A / Hable / Mobius / Reinhard / Clip / Perceptual，默认 Auto（按目标峰值自动选）。
- **Gamut Mapping：** Perceptual / Relative / Saturation / Absolute / Clip，默认 Perceptual。
- **可调参数（实时生效）：** 目标峰值亮度(nits)、白点、对比度恢复、饱和度、曝光、高光恢复开关。
- **多显示器：** 每张输出表面按所在显示器的 HDR 能力独立建链；窗口跨屏拖动时销毁重建该链（≤1 帧黑屏）。
- **色彩空间：** BT.601 / BT.709 / BT.2020 / DCI-P3 / sRGB 自动识别（容器标记优先，其次分辨率启发式），允许手动覆盖。

### 4.4 去隔行

自动检测 TFF/BFF/Progressive（含软电话片源 pulldown 标记）。算法：Auto / YADIF / BWDIF / Motion Adaptive / GPU Deinterlace，默认 Auto（BWDIF 1x）。

### 4.5 用户 Shader

- 支持 `.glsl` / `.hook`，加载前静态校验（禁止文件/网络 IO 内置函数）。
- 运行在渲染线程外的监控下：单帧耗时超预算连续 30 帧 → 自动卸载并 Toast 提示。
- Shader 目录沙箱化，仅允许读取 `shaders/` 目录。

### 4.6 帧同步与呈现

- 默认：D3D11 flip-model swapchain + Audio Master 时钟。
- Display Sync：按显示器刷新率微调音频时钟（±5% 内），消除周期性跳帧。
- 性能 HUD 实时暴露：FPS / Display Hz / Dropped / Repeated / VSync 状态 / A/V Drift。

## 5. 音频管线

### 5.1 解码

AAC/MP3/Opus/Vorbis/FLAC/ALAC/WAV/PCM/AC-3/E-AC-3/DTS/DTS-HD/TrueHD(+Atmos 元数据)/WMA/APE，经 FFmpeg；声道布局支持 2.0 至 7.1.4+。

### 5.2 输出路径

| 模式 | 说明 | 默认 |
| --- | --- | --- |
| WASAPI Shared | 系统混音器，兼容性最高 | ✓ |
| WASAPI Exclusive | 独占位完美输出，可选自动采样率切换 | 高级选项 |
| Bitstream Passthrough | AC-3/E-AC-3/DTS/DTS-HD/TrueHD 透传（SPDIF/HDMI），设备能力探测失败自动回落解码输出 | 关 |

### 5.3 处理功能

增益（-60dB ~ +30dB）、ReplayGain、Normalize、声道映射/Downmix/Upmix、平衡、音频延迟（±500ms）、10-band EQ + Parametric EQ、Limiter、Compressor。全部在 float32 域处理，输出前按需转目标格式。

---

## 6. 字幕管线

- 格式：SRT/ASS/SSA/VTT/SUB/IDX+SUB/SUP(PGS)/DVB Sub/Teletext；图形字幕经位图层合成，文本字幕走 libass 统一渲染。
- 编码：UTF-8/UTF-16/GBK/GB18030/Big5 自动嗅探，可手动覆盖。
- ASS 全特性：字体、描边、阴影、透明度、定位、Karaoke、Rotation、Scale、Fade、Clip、矢量绘制；字体附件从 MKV 提取，缺字体回退并记录。
- 渲染：libass 输出 RGBA 位图 → 在 libplacebo 合成阶段叠加（HDR 内容下字幕亮度单独映射，避免刺眼）。
- 自动匹配规则：同目录同名前缀 + 语言后缀（`.zh-CN.ass` 等），生成 中/繁/英/双语 候选菜单。
- 双语模式：主字幕 + 副字幕，位置可上下分布。

## 7. 网络与缓存

### 7.1 协议

HTTP/HTTPS/HLS/MPEG-DASH 首发；RTSP/RTMP/SRT/WebSocket 视引擎稳定性进入首发或二期；SMB/WebDAV/NFS/FTP/SFTP 二期经协议层适配。

### 7.2 缓存策略

```text
本地文件:   ring buffer 8 MB（小缓存, 快速 seek）
网络/HTTP:  动态缓存 目标 10–30s，按 bitrate × 实测带宽 × 延迟自动伸缩
DLNA 投屏:  预缓冲 ≥5s 起播，之后动态缓存
直播/不可 seek: 固定窗口缓存，禁用 seek UI
```

### 7.3 弱网恢复

连接中断 → 冻结最后帧 → 5s 指数退避重连（最多 N=5 次，可配置）→ 成功则按原位置续播；失败则错误卡片 + [重试]。网络层全程记录吞吐/延迟供 HUD 与诊断包使用。

## 8. 缩略图与章节

- 拖动进度条缩略图：后台 `aurora-thumb.exe` 按间隔（默认每 10s，可按片长自适应）预生成 160×90 WebP 缓存于 `cache/thumbs/<filehash>/`；拖动时仅读缓存，禁止实时全速解码。
- 章节：MKV/MP4 章节解析后在进度条打点 + 章节菜单 + 悬停缩略图。
- 快照（Ctrl+S）：从渲染链取**原始视频帧**（非 UI 截图），输出 PNG/JPEG/WebP；HDR 源可选保存 tone-mapped SDR 或原始 HDR 数据（高级）。

## 9. 状态机与 IPC

### 9.1 播放状态机

```text
IDLE → LOADING → READY → PLAYING ⇄ PAUSED
PLAYING → BUFFERING → PLAYING
* → ERROR → RECOVERING → (READY | IDLE)
* → STOPPING → IDLE
```

每次迁移带原因码，广播给 UI 与 DLNA 事件订阅方。

### 9.2 状态 Schema（核心字段）

```json
{
  "session_id": "uuid",
  "source": {"type": "local|http|hls|dlna", "uri": "...", "title": "..."},
  "state": "playing",
  "position_ms": 123450, "duration_ms": 7200000,
  "rate": 1.0, "volume": 80, "muted": false,
  "video": {"codec": "hevc", "profile": "main10", "w": 3840, "h": 2160,
            "bitdepth": 10, "fps": 23.976, "hdr": "hdr10",
            "color": {"primaries": "bt2020", "transfer": "pq", "matrix": "bt2020nc"}},
  "audio": {"codec": "truehd", "channels": 8, "layout": "7.1", "track_id": 2},
  "subtitle": {"codec": "ass", "lang": "zh-CN", "track_id": 4},
  "decode_path": "d3d11va-zero-copy", "renderer": "d3d11",
  "stats": {"dropped": 0, "repeated": 0, "av_drift_ms": 1, "buffer_pct": 82}
}
```

UI、DLNA 服务均订阅同一状态总线（单写者：引擎；多读者），杜绝状态分叉。

## 10. 自动性能降级

监控指标：GPU/CPU 占用、解码队列深度、渲染队列、Dropped Frames、VRAM。

```text
Dropped > 0.5% 持续 5s → 降 Shader（极致→高画质）
仍超标 → 降缩放算法 → 降后处理 → 关闭非必要滤镜
恢复 30s 稳定 → 不自动升档（防抖动），仅提示用户
```

**永不自动降低源分辨率/帧率。**

---

## 11. 崩溃恢复与安全

- 引擎进程看门狗：心跳 1s；失联 → 杀进程 → 重启 → 恢复会话（文件/进度/音轨/字幕/音量/窗口模式）。
- FFmpeg 固定版本并随更新升级 CVE；所有输入视为不可信：probe 阶段限制内存/时间，畸形容器直接拒绝。
- 网络 URL 白名单协议（http/https/hls/...），禁止 `file://` 经网络路径跳本地、防 SSRF（默认禁内网保留段以外的重定向，DLNA 局域网地址例外）。
- XML/NFO 解析禁用外部实体（XXE）；字幕脚本不执行任何外部调用。

---

## 12. 媒体数据库（SQLite）

WAL 模式、事务化写入、启动时 integrity_check + 自动迁移。表：`media / media_track / play_history / resume_position / subtitle / collection / playlist / favorite / device / dlna_session / settings`。断电后最多丢失最后一个事务。

---

## 13. 性能预算（启动与首帧）

| 指标 | 目标 | 手段 |
| --- | --- | --- |
| 冷启动 | ≤2.5s | 引擎懒加载、DLL 延迟加载 |
| 热启动 | ≤1s | 进程预热、托盘常驻可选 |
| 本地首帧 | ≤1s | probe 与解码并行、硬件解码预初始化 |
| 网络首帧 | ≤2s | 预缓冲阈值自适应 |
| 8K HDR 播放 | UI 60FPS | 渲染与 UI 分进程、零拷贝 |

## 14. 开放问题

1. D3D12 渲染链是否进入 1.0（建议 1.0 仅 D3D11，D3D12 作为 Beta 实验项）。
2. VVC/AVS3 解码库的授权与体积评估。
3. FSRCNNX/Anime4K 在低显存设备上的显存预算上限。
4. Bitstream 下 Atmos 元数据透传在 Windows 音频栈的兼容性白名单。

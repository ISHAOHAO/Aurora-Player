## 1. 审查范围与方法

本次审查覆盖 6 个官方内置主题：

```text
Cinema / Aurora / Noir / OLED / Glass / Immersive
```

审查材料：

- 真实 QA 截图：`player-cinema.png`、`player-aurora.png`、`player-noir.png`、`player-oled.png`、`player-glass.png`、`player-immersive.png`

审查维度：

1. Theme Personality（人格是否独立）
2. Theme Difference（是否只是换色）
3. Typography（是否形成不同语言）
4. Surface（matte / paper / flat / glass / luminous / atmospheric 是否成立）
5. Layout（是否真正改变空间结构）
6. Particle（是否有真实 depth 与主题语言）
7. Immersive（是否是真正的 digital theatre）
8. Video First（效果是否影响观影）

## 3. 逐主题视觉判断

### 3.1 Cinema — Modern Cinema Equipment

**代码意图：** 暖琥珀 #E8A94E、matte 表面、矩形控件、editorial-sans、grain 0.6、低密度慢速粒子。

**截图观感（暗场播放）：**

- 黑场极其干净，几乎纯黑。
- 顶部窗口控制轻，右侧「视觉」入口低调。
- 粒子表现为稀疏的小白点，均匀分布在黑色画面上。
- 整体确实非常「不抢戏」，Video First 成立。

**优点：**

- 黑色干净、UI 克制、粒子不抢戏。
- 顶部控件和右侧入口都足够低调。
- 在播放暗场内容时，观众几乎不会意识到视觉层的存在。

**问题：**

- **粒子更像「星空/屏保」而不是「电影尘光」**。当前粒子是 uniform 的白色圆点，缺少：
  - 前后景深度（虽然 `depth=0.3`，但视觉上不明显）
  - 尺寸/速度/透明度的显著分层
  - 模糊与光晕变化
  - 不均匀密度（dust 应该有聚集和空白区域）
- 在暗场视频下，Cinema 与 Aurora/Glass/Immersive 的差异被压缩到几乎只剩粒子密度和右上角 accent 色，**人格辨识度不足**。

**结论：** Cinema 的「设备感」和「克制感」成立，但粒子语言有 screensaver 味，是 6 主题中最容易 first impression 变廉价的地方。

---

### 3.2 Aurora — Luminous Atmospheric Interface

**代码意图：** 青紫 #5FD0F2、高亮氛围、cover 跟随、更圆润、更宽松、密度 0.52、depth 0.62。

**截图观感（暗场播放）：**

- 与 Cinema 相比，粒子略多、略亮、略快。
- 由于播放页 opacity 被压到极低，背景 gradient 和 lighting 几乎不可见。
- 整体仍然是「深色画面 + 小白点」。

**优点：**

- 参数上确实比 Cinema 更「发光」：intensity 0.62 vs 0.25、density 0.52 vs 0.22、bloom 0.30 vs 0.10。
- Home/Library 的 layout 更宽松、圆角更大（`radius=14`）。

**问题：**

- 在播放页暗场下，Aurora 与 Cinema 的区别**主要靠粒子密度体现**，而不是「发光氛围」本身。
- 粒子颜色和 Cinema 一样是白色，没有利用青紫 accent 做光色差异化。
- 「luminous」的人格在播放页被 Video First 约束吃掉太多，需要 Home/Library 或亮场 cover 才能体现。

**结论：** Aurora 有明确的人格定义，但暗场播放时和 Cinema 拉不开差距；需要依赖非播放场景才能表达「发光氛围」。

---

### 3.3 Noir — Film Archive / Editorial

**代码意图：** Georgia 衬线、纸面、sharp、编号章节、纵向索引、低密度、高 grain、无氛围光。

**截图观感（暗场播放）：**

- 黑场干净，粒子极少（`density=0.12`）。
- 由于播放页主要显示视频 + 底部控制条，Noir 最大的 layout 差异（海报轨变纵向索引、编号章节、隐藏 shortcuts）**在播放页完全不可见**。
- 底部控制条和其他主题几乎一样。

**优点：**

- 代码层面的人格最强烈：typography=serif、shape=sharp、density=spacious、layout=editorial。
- grain 0.85 营造胶片/档案感，播放页也能轻微感知。
- 粒子最少，最克制。

**问题：**

- 播放页无法展示 Noir 的核心差异（排版与布局）。
- 若只看播放页，Noir 容易被误认为「粒子更少的 Cinema」。

**结论：** Noir 在 Home/Library 应该最有辨识度，但在播放页的存在感最弱；这不是错误，而是它的人格定位决定的。需要确认用户在 Home/Library 的实拍是否足够有 editorial 感。

---

### 3.4 OLED — Reference Display / Minimal Display Mode

**代码意图：** Dark=纯黑 #000、Light=#FBFBFB 亮白参考、无氛围、无粒子、flat、compact。

**截图观感（暗场播放）：**

- OLED Dark：几乎纯黑，无任何可见粒子或氛围光。
- 这是 6 主题中唯一在暗场下也能明确感知人格的主题——**因为它主动取消了所有氛围**。
- 顶部控件保持可见但不喧宾夺主。

**优点：**

- 人格最清晰：「参考显示模式」。
- OLED Dark 真正做到了纯黑节能、零视觉噪音。
- OLED Light 在截图 `final-white-immersive.png` / `bright-white-immersive.png` 中可见为干净亮白底，没有氛围光污染。

**问题：**

- 无。OLED 的目标就是「没有氛围」，它已经做到了。
- 唯一需要注意的是：在 OLED Light 下，其他 UI 元素是否保持了足够高的对比度（代码中 `text=#0B0B0B`、`surface=#FFFFFF`，对比度足够）。

**结论：** OLED 是 6 主题中人格最明确、最不容易被误认为 screensaver 的主题。完成度最高。

---

### 3.5 Glass — Translucent Control Surface

**代码意图：** 半透明控制面、高 glass 0.85、强 blur 36px、紫色 accent #9D8CFF、cover 跟随。

**截图观感（暗场播放）：**

- 播放页暗场下，Glass 与 Cinema/Aurora 差异不明显。
- Console 打开时，glass 材质在面板中可见（`console-open.png` 中 Console 本身是玻璃面板，但这不是 Glass 主题专属）。
- 粒子密度 0.25，速度和 Cinema 接近。

**优点：**

- 代码层面 surface=glass、shape=translucent、ui.glass=0.85，Home/Library 的磁贴/封面会有玻璃材质。
- accent 紫色在 Console 和 UI 中能提供一定辨识度。

**问题：**

- 播放页暗场下，Glass 的核心差异（半透明浮层面板）几乎不可见。
- 粒子仍然是白色圆点，和 Cinema/Aurora 同族。
- 如果用户没有进入 Home/Library，可能感觉不到「Glass」与其他主题的本质区别。

**结论：** Glass 的人格需要 Home/Library 场景才能表达；播放页辨识度一般。但它的设计语言和 OLED 一样清晰，只是应用场景受限。

---

### 3.6 Immersive — Digital Theatre

**代码意图：** cover 环境、强氛围、粒子多/反应强、UI 最少、bloom/vignette/grain 全开、motion 启用。

**截图观感（暗场播放）：**

- 与 Cinema 相比，粒子更多、更快，中心区域有轻微光晕。
- 在 `player-immersive-console.png` 中，Console 的 accent 是橙色 #F59E62，与 Cinema 的琥珀色接近但略偏橙。
- 亮场截图 `final-white-immersive.png` 中可见明显的 cover-derived 浅色氛围，有「环境围绕视频」的感觉。

**优点：**

- 参数上确实最丰富：intensity 0.82、density 0.74、depth 0.82、reaction 0.72、bloom 0.36、vignette 0.50。
- 在亮场/浅色内容下，cover-derived 环境光能形成明显的「数字剧院」空间感。
- UI opacity 最低（0.68 / controlOpacity 0.50），符合「更少 UI」的承诺。

**问题：**

- 暗场播放时，Immersive 仍然主要由「更多白色圆点」来体现，和 Cinema 的差异是量变而非质变。
- 如果没有 cover palette（例如黑场、纯黑过渡），Immersive 会退化为「粒子更多的 Cinema」。
- 橙色 accent 和 Cinema 的琥珀色在暗色调下容易混淆。

**结论：** Immersive 在亮场/cover 内容丰富时最有说服力，暗场时依赖粒子密度来区分。它确实比 Cinema 更丰富，但是否达到「完全不同的 Digital Theatre」仍有提升空间。

## 4. 关键对比组判断

### 4.1 Cinema vs Immersive

- **差异程度：** 中等。Immersive 粒子更多、光晕更强、UI 更少，但基础视觉语言（白色圆点 + 暗色背景）相同。
- **是否像两个产品：** 不像。更像是同一产品的「标准模式」和「增强模式」。
- **建议：** 如果希望 Immersive 真正像 Digital Theatre，需要让粒子/氛围与 cover 内容产生更强关联（颜色、空间深度、运动方向），而不是单纯增加密度。

### 4.2 Cinema vs Aurora

- **差异程度：** 较弱。暗场下主要靠粒子密度区分，颜色和光感差异不明显。
- **是否像两个产品：** 不像。
- **建议：** Aurora 的「青紫发光」在播放页几乎被 opacity 压制，需要让 accent 色更主动地渗入粒子/环境光，或者在非播放场景更强调圆角/宽松布局。

### 4.3 Cinema vs Noir

- **差异程度：** 播放页较弱，Home/Library 应该较强。
- **是否像两个产品：** 播放页不像，Home/Library 可能像。
- **建议：** 这是设计定位决定的，不是错误。需要确认 Home/Library 的实拍是否充分展现了 Noir 的 editorial 布局。

### 4.4 Noir vs OLED

- **差异程度：** 强。
- Noir = 纸面、衬线、编号、高 grain、极少粒子。
- OLED = flat、technical、纯黑/纯白、无粒子、无氛围。
- **是否像两个产品：** 在各自的目标场景下像。
- **建议：** 两者都是高完成度的主题，保持当前方向即可。

### 4.5 Cinema vs Glass

- **差异程度：** 播放页较弱，Home/Library 应该较强。
- Glass 的核心是半透明面板材质，播放页没有面板时无法体现。
- **建议：** 同 Noir，需要在 Home/Library 验证其实际效果。

### 4.6 OLED Light vs OLED Dark

- **差异程度：** 极强。
- Dark = 纯黑影院，Light = 亮白参考模式。
- 从截图看，Light 模式下没有强氛围光，保持干净高对比。
- **结论：** 这是 6 主题中 light/dark 差异最大、最成功的一对。

## 5. 总体判断

### 5.1 什么已经很好

1. **工程 QA 扎实。** Video First 不是口号，而是通过 opacity 上限、中心避让、blend 模式、节流缓存等技术手段强制实现的。
2. **架构解耦清晰。** Theme / Appearance / Presentation 三个维度互不污染，Custom persistence 完整。
3. **OLED 完成度最高。** 6 主题中人格最明确、辨识度最高、最没有 screensaver 味。
4. **Noir 的设计语言最独特。** 一旦进入 Home/Library，它应该是最不像其他主题的一个。
5. **Visual Console 定位准确。** 导演台而非设置抽屉，UI 让位、实时调参、持久化边界都正确。

### 5.2 什么还有 generic / screensaver / SaaS template 味

**主要问题集中在粒子系统。**

当前粒子系统的实现：

- 所有主题共用同一套白色圆点。
- 仅通过 `density / speed / size / opacity / depth` 做参数微调。
- 没有按主题调色（Cinema 暖尘、Aurora 青紫光、Noir 纸屑/单色调、Glass 反光微粒、Immersive 多彩 depth）。
- 没有形状变化（全是完美圆形）。
- 没有模糊/光晕变化（全是硬边小圆点）。
- 没有空间深度叙事（foreground/mid/background 的分布、密度、运动方向没有主题化）。

这导致：

> Cinema 的粒子像星空屏保。  
> Aurora 的粒子像发光星空屏保。  
> Immersive 的粒子像更密集的星空屏保。

这是目前 6 主题中最容易让人联想到「AI 生成 / screensaver / SaaS template」的地方。

**次要问题：播放页主题差异被过度同质化。**

由于 Video First 硬约束，暗场播放时 6 主题看起来都接近「黑色 + 小白点 + 右侧视觉入口」。这虽然符合 Video First，但也让主题人格在最重要的观影场景中被严重削弱。

这不是要求违反 Video First，而是说明：**如果要在播放页表达人格，必须依靠粒子、UI 细节、 accent 色、以及亮场/cover 内容下的氛围；当前粒子系统无法承担这个任务。**

### 5.3 6 主题是否像 6 个设计人格？

| 主题 | 人格清晰度 | 播放页辨识度 | 是否存在 screensaver 味 |
|---|---|---|---|
| Cinema | 中 | 低 | 粒子有 screensaver 味 |
| Aurora | 中 | 低 | 粒子有 screensaver 味 |
| Noir | 高 | 低（播放页无法展示 layout） | 无 |
| OLED | 极高 | 高 | 无 |
| Glass | 高 | 低（播放页无面板） | 无 |
| Immersive | 中高 | 中 | 粒子有 screensaver 味 |

**结论：** 6 主题在代码层面确实拥有不同的人参，但在播放页暗场场景下，差异被压缩；粒子系统是拉低整体辨识度的共同短板。

## 6. 下一步建议

### 6.1 不建议现在做的事

- ❌ 新增主题
- ❌ 新增 Visual Engine
- ❌ 修改 mpv / HDR / DLNA / 播放逻辑
- ❌ 重写 Settings / Player
- ❌ 单纯增加粒子密度来「更炫」
- ❌ 把 6 主题变成 6 个不同 App

### 6.2 建议做 P2 视觉 tuning（小范围、有依据）

优先级最高的是**粒子系统的人格化**，这是目前唯一在播放页暗场下仍然可见、却最缺乏主题语言的元素。

具体 tuning 方向：

| 主题 | 当前粒子 | 建议方向 |
|---|---|---|
| **Cinema** | 白色稀疏圆点 | 暖琥珀/淡金粒子、轻微模糊、更大尺寸分层、更慢速度、模拟「放映厅尘光」 |
| **Aurora** | 白色中密圆点 | 青紫/蓝白粒子、soft glow、更圆润的运动轨迹、与 accent 色一致 |
| **Noir** | 白色极少圆点 | 单色调米白/浅灰、略带纸屑/胶片颗粒感、速度极慢、数量极少 |
| **OLED** | 无 | 保持无粒子 |
| **Glass** | 白色少量圆点 | 冷白/淡紫反光微粒、偶有「玻璃碎片」高光、运动更平滑 |
| **Immersive** | 白色密集圆点 | 多彩、与 cover palette 联动、强 depth 分层、有前后景速度差、模拟剧院空气感 |

实现上不需要新增引擎，只需要扩展 `ParticleEngine`：

- 按主题传入粒子颜色（可基于 accent + palette）。
- 增加形状/模糊参数（圆点可带 `shadowBlur` 或改用径向渐变填充模拟 glow）。
- 按 depth 分层：前景粒子更大、更亮、更快、更模糊；背景粒子更小、更淡、更慢。
- 增加「不均匀分布」：某些区域密度高、某些区域空白，避免 screensaver 均匀感。

### 6.3 其他可选 P2 tuning

1. **Cinema 与 Immersive 的 accent 色区分**
   - 当前 Cinema #E8A94E（暖琥珀）与 Immersive #F59E62（橙）在暗色调下太接近。
   - 可考虑把 Immersive accent 调得更饱和或更偏红/铜色，强化「剧院幕布」感。

2. **Noir 的播放页字体提示**
   - 播放页虽然没有海报轨，但可以在时间码、文件信息等处使用衬线/等宽字体组合，强化 editorial 感。

3. **Aurora 的发光感在播放页表达**
   - 当前播放页 lighting intensity 被 opacity 压缩，可考虑让 Aurora 的环境光在 cover 内容丰富时更明显地溢出到画面边缘。

4. **Home/Library 实拍确认**
   - 当前 QA 截图全部是播放页。建议补拍 Home/Library 在 6 主题下的真实截图，验证 Noir/Glass/Aurora 的 layout 差异是否足够明显。

### 6.4 是否值得让 OpenCode 做 P2 tuning？

**值得。** 但范围要限定：

- 只动 `ParticleEngine.ts` + `registry.ts` 中粒子相关参数。
- 不改架构、不改性能预算、不改 Video First 约束。
- 以「主题人格」为目标，不以「更炫」为目标。
- 每改一个主题都要跑 `visual-test` + 黑场/白场采样 + 真实播放 QA，确保没有回归。

## 7. 最终结论

Aurora Player 的 Visual System 在工程层面已经完成得非常扎实。Video First、状态预算、OLED Light/Dark、Appearance 独立维度、Console 导演台定位都正确落地。

目前最大的审美短板不是架构，而是**粒子系统过于 generic**：6 个主题共用同一种白色圆点语言，导致 Cinema/Aurora/Immersive 在暗场播放时容易让人联想到星空屏保，而不是各自的设计人格。

6 主题中：

- **OLED** 完成度最高，人格最清晰。
- **Noir / Glass** 的人格依赖 Home/Library 场景，播放页辨识度低是设计定位决定的。
- **Cinema / Aurora / Immersive** 共享同一套粒子语言，是 P2 tuning 收益最大的三个主题。

建议下一步：**小范围、有依据地人格化粒子系统**，让 Cinema 像电影尘光、Aurora 像青紫发光、Immersive 像数字剧院空气，而不是三种不同密度的星空屏保。
